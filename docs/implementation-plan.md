# Implementation plan

## Milestones and acceptance criteria

1. **Foundation** — Create a Next.js App Router frontend, FastAPI API, local service configuration, health endpoint, and runnable instructions. Verify backend tests and frontend type-check/build.
2. **UI and navigation** — Deliver an accessible responsive shell, working navigation for implemented pages, and clear disabled states for unfinished areas.
3. **Authentication and database** — Add secure registration/session flows, PostgreSQL models and migrations, and user-isolation tests.
4. **Market data** — Select a licensed provider, implement validated provider adapters, caching and freshness metadata; no credentials or live provider are currently configured.
5. **Screener and indicators** — Add validated AND/OR filters, persistence, tested indicators, and paginated results using supported data.
6. **Charts and patterns** — Add historical charts and explainable, look-ahead-safe pattern rules.
7. **Backtesting** — Add deterministic strategy execution, costs, reporting, and tests for timing and bias.
8. **Portfolio and risk** — Add transaction accounting, ownership authorization, performance, and aligned risk metrics.
9. **News and AI** — Integrate permitted news and backend-only Gemini explanations grounded in validated data.
10. **Watchlists and alerts** — Add persistent lists, alert lifecycle, cooldowns, and a single-instance scheduler.
11. **Quality assurance** — Run automated and browser tests, resolve critical failures, and document limitations.
12. **Deployment and documentation** — Prepare and verify hosted services when credentials and hosting access are provided.

## Acceptance gate

The product is complete only after the relevant application workflows, security controls, tests, data provenance, and deployment status have been verified. Do not treat disabled navigation, illustrative data, or scaffolding as complete functionality.

## Current milestone state

- **Foundation and initial UI:** implemented; local API and frontend builds have been verified.
- **Authentication and database:** implemented with SQLite/PostgreSQL SQLAlchemy models, Alembic migration, Argon2 password hashing, revocable HTTP-only sessions, owner-scoped resources, and sign-in/register pages. Browser checks verified registration, correct and incorrect password login, duplicate registration, invalid email/weak password rejection, session persistence after refresh, logout revocation, and watchlist/alert isolation across two users. Backend tests verify invalid and expired cookie sessions (expired sessions are removed). Temporary browser-test users and data were deleted. Email verification, password reset, and session cleanup scheduling remain pending; PostgreSQL runtime is unverified because no PostgreSQL service is available.
- **Market data:** provider protocol, validated user-supplied daily CSV adapter, and optional Finnhub daily-historical-candle adapter are implemented with bounded date filtering, five-minute caching (including symbol search), NSE/BSE result filtering, strict OHLCV/chronological validation, provenance, India-market freshness labels, and explicit unavailable/error states. CSV rejects duplicate headers/rows, malformed numeric values, duplicate timestamps, out-of-order data, and repeated Asia/Kolkata market dates; filters use the same market-date timezone. Provider selection is explicit; no automatic Finnhub-to-CSV or demo fallback occurs. Environment names are `MARKET_DATA_PROVIDER`, `FINNHUB_API_KEY`, `FINNHUB_SYMBOLS`, `MARKET_DATA_CSV_DIR`, and `NEXT_PUBLIC_API_BASE_URL`; the Finnhub key is backend-only. Finnhub's public [candle docs](https://finnhub.io/docs/api/stock-candles), [symbol docs](https://finnhub.io/docs/api/stock-symbols), and [pricing](https://finnhub.io/pricing) do not establish this account's NSE/BSE entitlement; no credential or provider is configured, so live authenticated requests and instrument coverage are not verified. No real-time/delayed quote feed is integrated; CSV rights and accuracy remain the user's responsibility.
- **Screener, indicators, charts, patterns, and stock analysis:** historical screener, AND/OR rules, pagination/sorting, saved screens, SMA/EMA/RSI/MACD/relative volume, daily candlestick/volume SVG charts, and explainable look-ahead-safe historical range breakouts are implemented. `/analysis` adds debounced provider-backed search, NSE/BSE selection, date validation, historical performance metrics, and explicit source/freshness/as-of labels with stale and empty-data states. SMA/EMA/RSI/MACD use documented seeds/smoothing and null warm-up values. Performance uses first-to-last close return and annualized sample volatility of adjacent available close-to-close simple returns (`sqrt(252)`); missing sessions are not filled and a multi-session gap remains one observation. Dividends/corporate actions are not adjusted. Only one documented pattern rule is currently available. Browser verification covered route rendering, unavailable-provider search/load errors, and invalid-symbol/reversed-date handling; the latest as-of/stale/empty-data presentation is covered in code but real provider data is not available to validate chart rendering.
- **Backtesting:** two reproducible daily strategies, next-open execution, fees/slippage, stop/take-profit, position sizing, trade log, equity curve, and performance metrics are implemented and tested. Corporate actions, taxes, and benchmark comparison are not modeled.
- **Portfolio and risk:** user-isolated portfolios, starting cash, editable transactions, weighted-average cost accounting, historical-close valuation, aligned-return volatility/drawdown/correlation, and allocation summaries are implemented. Sector data and performance history are not available.
- **News/AI:** Finnhub source-linked news API/page and backend-only Gemini article summaries are implemented. The stock-analysis page includes authenticated `POST /api/v1/research` combining configured daily history, existing indicators/performance calculations, optional Finnhub company articles, and optional Gemini explanations. Responses separate data/news/AI statuses, source links/timestamps, risks and limitations; provider failures do not create fallback facts. Request inputs are bounded and validated, origin checked, and the endpoint is limited to five requests per user per minute per process. Prompt instructions treat external article text as untrusted data. Mock tests cover configured/missing Gemini, failures, missing sources, source references, auth, validation, rate limiting and injection content. Smoke-test audit verified `GEMINI_API_KEY` and optional `GEMINI_MODEL` configuration names, `gemini-2.5-flash` current configured default, `load_dotenv()` at backend import, and `.env` ignored/untracked. No `.env`, Finnhub key, Gemini key, or user CSV is configured, and no authorized local session is available; real key loading after restart, provider requests, and authenticated populated-panel rendering remain blocked. This is not a verified live assistant. Rate limiting is process-local, and provider terms/entitlements need deployment review.
- **Watchlists/alerts:** private CRUD, configurable threshold rules, cooldowns, read/unread history, daily-history freshness guards, per-bar database deduplication, manual polling, and a single-process configurable scheduler are implemented. Alerts operate only on user-supplied historical CSV bars; no live-price or email/push notification service is provided.

Milestone 4 full verification passed: `python -m pytest` (84 tests), `npm run test` (1 test), `npm run build` (including `/analysis`), `python -m compileall backend alembic`, and `npm run typecheck` (after build completion). The current real-AI smoke-test task reran these same five commands successfully: 84 backend tests, 1 frontend test, type-check, production build, and Python compilation. Focused research/news tests passed earlier (43 tests). Coverage includes research auth/origin/inputs/rate limit, source status/failures, news refs, Gemini configured/missing/malformed responses, and injection text marked untrusted. Browser verified research panel/periods and unauthenticated response with sign-in link; no populated authenticated response or real AI/provider request was made. Live market data and AI remain unverified without credentials. PostgreSQL runtime verification and public-production security hardening remain pending.
